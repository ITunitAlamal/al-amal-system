# AIMS 2.0 — قسم شؤون الأيتام والكفالات: خطة التنفيذ (المرحلة 0)

المرجع: `AIMS_2_0_Claude_Complete_Implementation_Smart_Import_Final.md`.
الإزالة السابقة: `docs/audits/AIMS_ORPHANS_DECOMMISSION_2026-10-31_AR.md`.

**قرارات تنفيذ ثابتة**
- **الاختبارات:** لا اختبارات آلية ولا بيانات اصطناعية (قرار المالك يتقدم على بند 13). البديل: فحوص قراءة فقط على النظام الحقيقي، بسكربتات في مجلد مؤقت.
- **المواقع والقيم:** لا جغرافيا مكتوبة في الكود. المواقع من `GazaGeography` بأربعة مستويات، وكل القيم القابلة للتعديل من «ثوابت النظام» (المجموعات `orphans` و`sponsorships` و`relief` و`social` و`education`).
- **قراءة Excel:** `App\Support\Spreadsheets\StreamingXlsxReader` (قراءة متدفقة). **التصدير:** `App\Support\Reports\TabularXlsx`.
- **المخازن:** حركات `finance_stock_movements` (`reference_type='campaign'`)، ولا دفتر مخزون موازٍ.
- **الحسابات:** `finance_receivables` و`finance_transactions` عبر `FinanceSourceBridge` (الوحدة `sponsorships`)، ولا دفتر مالي موازٍ.
- **المدير التنفيذي:** هويته دور `executive_director`. اعتماده للكشوف حصري: تحقق في الخدمة وtrigger في قاعدة البيانات، دون تفويض.

## 1. نموذج البيانات (ERD مختصر)

```
persons ─┬─ person_status_events (حالة الحياة/الوفاة/الفقد بتاريخ سريان)
         ├─ registry_addresses (أصلي/حالي/نزوح؛ لشخص أو لأسرة، واحد فقط)
         ├─ economic_assessments (حالية أو قبل الوفاة؛ لشخص أو أسرة)
         ├─ care_records (احتياجات صحية/دعم؛ التفاصيل السريرية مشفرة ومقيدة)
         └─ registry_documents
orphans (person_id فريد) ─┬─ orphan_parent_links (father/mother → persons؛ يُشارك بين الإخوة)
                          ├─ orphan_guardianships ── orphan_guardians (person_id فريد) ── guardians (حساب البوابة)
                          ├─ education_records (سنة بسنة)
                          └─ social_assessments / benefit_records / sponsorship_beneficiaries
households ─ household_members (persons، بتواريخ) ─ registry_addresses ─ social_assessments
portal_applications ─ portal_application_children (ادعاء لكل طفل) ─ portal_application_events
orphan_appeals → (orphan|household|guardian) + campaign
sponsors ─ sponsorships ─ sponsorship_beneficiaries (orphan|household)
assistance_requests ;  benefit_records (تسليم مؤكد فقط، إلحاق مع عكس)
campaigns ─ campaign_items (صنف مخزن/مقاس) ─ campaign_quotas ─ campaign_rule_versions (ثابتة)
          ─ campaign_runs (ثابتة) ─ campaign_candidates (درجة + تفسير + لقطة)
          ─ campaign_lists (إصدارات) ─ campaign_list_entries ─ campaign_change_requests
          ─ campaign_members (وصول محدود) ─ campaign_duplicate_alerts ─ campaign_deliveries ─ campaign_delivery_events
import_batches ─ import_staged_rows ─ import_row_issues ; import_mapping_profiles ; import_execution_events ; orphan_export_log
```

**قيود جوهرية**
- كل يتيم ليس في حالة `ended` أو `archived` له رابط وصاية حي واحد على الأقل (claimed/pending/approved). يفرضه trigger مؤجل (deferred).
- لا يتكرر رابط حي بين الطفل والوصي نفسه.
- الحد الأقصى رابط رئيسي (`is_primary`) واحد لكل يتيم.
- رقم الهوية نص مشفر، مع hash للمطابقة التامة. الفهرس الفريد يشمل صيغة الهوية الصحيحة فقط؛ الأرقام الوهمية (placeholder) تُعلَّم ولا تُعدّ تحققًا.
- بوابة المستفيدين تعرض ملف الطفل فقط إذا تحققت الثلاثة: الحساب معتمد، ووصاية معتمدة لهذا الطفل، ونافذة بتاريخ اليوم.
- **كشف الحملة:**
  - الإصدار المعتمد ثابت؛ قيوده وحالته تُحمى بـ trigger.
  - الانتقال إلى `approved` يُرفض في قاعدة البيانات إن لم يكن صاحب القرار يحمل `executive_director`.
  - كل تعديل على كشف معتمد يأتي في طلب تعديل يحمل الفرق (diff) وإصدارًا جديدًا.
- **التسليم:** مفتاح عدم تكرار (`idempotency_key`) فريد. السجل يُلحَق فقط، والتصحيح بحدث عكسي. سجل الاستفادة لا يُنشأ إلا من تسليم مؤكد.

## 4. قائمة التنفيذ

- [x] **1. الأساس:** الجداول، وقدرات الموظفين، والإعدادات، وفئات العمر في الثوابت، والقائمة (6 مداخل).
- [x] **2. السجل:** إنشاء الوصي واليتيم معًا في معاملة واحدة، والبحث (الهوية تامة، الاسم الرباعي)، والفلاتر، والمعاينة، والملفات، واستبدال الوصي، وتحذيرات التكرار.

- [x] **4. اللوحة:** مؤشرات بتعريفات موثقة، ومخطط جغرافي وعمري مع الانتقال إلى السجل، وطابور «يحتاج إلى إجراء»، وتوزيع العمل.
- [x] **5. الكفالات:** الكفلاء والكفالات والتغطية، والربط بالحسابات، وسجل الاستفادة.
- [x] **6. الحملات:** المعالج، وإصدارات القواعد، والمحاكاة، والكشوف، واعتماد المدير التنفيذي، وطلبات التعديل، والمخازن، والتسليم بلا تكرار، والتسوية.
