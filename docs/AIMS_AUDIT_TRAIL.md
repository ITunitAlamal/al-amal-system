# «سجل النظام» — السجل المركزي للتدقيق (2026-11-01)

## 1. القرار المعماري
- **مصدر واحد للحقيقة:** `audit_logs` بقي هو السجل الوحيد، ووُسِّع بدل إنشاء جدول موازٍ.
- **مدخل موحد للكتابة:** كل الكتّاب يمرون بمشغّل `BEFORE INSERT` واحد (`aims_audit_fill`):
  - `AuditService`، ويُستدعى من 53 موضعًا.
  - `AuditLog::create`.
  - 15 موضع إدراج مباشر.
- **جداول أحداث الوحدات:** بقيت مصدر تفاصيلها. يُضاف لكل حدث منها صف مرجعي في السجل المركزي داخل المعاملة نفسها، دون نسخ البيانات.

## 2. ما يُسجَّل ومصدره

| الوحدة | الأحداث | مصدر الالتقاط |
|---|---|---|
| الأمن والدخول | دخول/خروج، **دخول فاشل** (بصمة HMAC لاسم الدخول لا الاسم نفسه)، إيقاف مؤقت (429)، تغيير كلمة المرور، **رفض الوصول 403** (مرة لكل حساب ومسار كل 10 دقائق)، إعادة تعيين كلمة مرور موظف، الأدوار والتكليفات | `AuthController`، `ForcePasswordChangeController`، `AuditDenials`، كتّاب قائمون |
| بوابة المستفيدين | دخول، خروج، فشل، تغيير/استعادة كلمة المرور، أحداث طلب الأسرة (لكل طفل) | `GuardianPortalController`، جسر `portal_application_events` |
| المدير التنفيذي ومسارات العمل | كل قرار في مسار: اعتماد، رفض، إعادة، توصية، تقديم | جسر `workflow_events` |
| كشوف الحملات | إعداد، إرسال، سحب، تعديل، طلب تعديل، قرار المدير التنفيذي (قائمة)، **محاولة القرار دون صلاحية = حدث حرج** `orphans.campaign.list.decision_denied` | `Campaigns` (قائم) + `AuditDenials` |
| شؤون الأيتام | التسجيل، والوصاية لكل طفل، والملفات، والاستيراد (رفع، إلغاء، استئناف، إعادة فحص، اعتماد مبدئي)، والتصدير، والاطلاع على ملف حساس، والحالة الحيوية | كتّاب قائمون + جسور `orphan_export_log`، `orphan_access_log`، `person_status_events` |
| التسليم الميداني | أحداث الجهاز ومراجعتها وحل تعارض المزامنة | جسر `field_events` (إدراج + تغيير الحالة) |
| الحسابات | إسناد الصلاحيات المالية، والسندات، والتصدير… | جسر `finance_audit_events` |
| الدوام | الجداول، والمزامنة، والتصحيحات، والطلبات | جسر `attendance_audit_events` |
| الموارد البشرية | الملفات، والاستيراد، وتغييرات الأجر، وإجراءات HR | كتّاب قائمون + جسر `employee_hr_action_events` |
| الأصول والإيجارات | عمليات الإيجار، وحالة العين | `RentalAudit` + جسر `aims_property_unit_status_events` |
| الهيكل والمراسلات والإعدادات والقائمة والمؤشرات | قائمة كما كانت | كتّاب قائمون |
| سجل النظام نفسه | تصدير السجل، وانقطاع السلسلة | `AuditLogController`، `audit:seal --verify` |

**لا يُسجَّل:**
- قراءة كل صفحة.
- نبضات المهام الناجحة.
- كل صف في الاستيراد؛ تفصيل الصف في `import_execution_events`.

## 3. الحقول الجديدة (migration `2026_11_30_000012`، إضافات فقط)

| المجموعة | الحقول |
|---|---|
| الهوية والوقت | `event_id` (UUID فريد)، `schema_version`، `occurred_at`، `recorded_at` (timestamptz) |
| المنفّذ | `actor_type` (user/guardian/worker/system)، `actor_guardian_id`، `actor_label` (نسخة الاسم وقت الحدث)، `department_id` |
| السياق | `origin` (staff/portal/worker/api/system)، `guard`، `route_name`، `request_method`، `correlation_id` |
| التصنيف | `module`، `submodule`، `outcome` (success/failure/denied)، `reason_code`، `severity` (info/notice/warning/critical)، `sensitivity` (normal/personal/restricted)، `subject_ref` |
| الختم | `seal_seq`، `prev_hash`، `row_hash` |

**الفهارس:**
- `occurred_at`.
- (`module`, الوقت)، (`actor`, الوقت)، (`department`, الوقت).
- `action`.
- النتائج غير الناجحة (جزئي).
- `correlation_id`.
- غير المختوم.
- `event_id` و`seal_seq` (فريدان).

**جدول `audit_seals`:** مراسي الختم.

**الصفوف القديمة (1,281 + ما كُتب حتى التشغيل):** أُثريت بالحقول المشتقة مرة واحدة، ولم يُمس أي حقل أصلي.

## 4. الخصوصية
- **`AuditService` يطبق:**
  - **أسرار:** كلمة مرور، رمز، OTP، جلسة، توقيع… لا تُخزن، وتُستبدل بـ«[محجوب]».
  - **بيانات محمية:** رقم الهوية، الصحة، الإعاقة، ظروف الفقد، الملاحظات المقيدة، `form_data`… تُخزن «تغيّر — بيانات محمية» فقط.
  - **النصوص:** تُقص عند 500 حرف، وتُزال منها محارف التحكم (منع حقن السجل)، والعمق محدود.
- **المشغّل:** يستبدل أي حمولة فوق 16KB بحجمها فقط.
- **العرض:**
  - القائمة لا تحمل أي حمولة.
  - التفاصيل المقيدة لا تظهر لأحد.
  - تفاصيل البيانات الشخصية للإدارة العليا فقط.
  - عنوان IP مقنّع لغير الإدارة العليا.
- **التصدير:** بلا حمولة وبلا IP، ومحمي من حقن الصيغ، و20,000 صف حدًّا أقصى، ويُسجَّل هو نفسه.

## 5. من يرى ماذا (`AuditScope`، على الخادم في كل استدعاء)

| القارئ | ما يراه |
|---|---|
| مدير النظام والمدير التنفيذي | الكل. الصلاحية التقنية لا تمنح اعتمادًا تنفيذيًا |
| رئيس القسم المعيّن | أحداث موظفي قسمه ووحداته فقط، دون المقيد ودون أحداث الأوصياء والنظام. فلتر القسم لا يوسع نطاقه |
| بقية الموظفين | 403، ويُسجل الرفض |
| الأوصياء | لا وصول. يرون سجل طلبهم الآمن في البوابة |

**الواجهة:**
- مدخل واحد: «الإعدادات والصلاحيات ← سجل النظام».
- **«سجل التغييرات» السياقي:** في الحملة (يشمل إصدارات الكشوف) ودفعة الاستيراد، وموجود سابقًا في ملف اليتيم وملف الموظف.

## 6. الموثوقية وكشف العبث
- **ارتباط بالمعاملة:** الكتابة داخل معاملة التغيير، فالتراجع لا يترك ادعاء نجاح (مُختبر). الرفض يُسجَّل بعد تراجع العمل المرفوض.
- **الإضافة فقط:** `UPDATE` و`DELETE` و`TRUNCATE` مرفوضة بمشغّلات. الاستثناء الوحيد كتابة حقول الختم مرة واحدة.
- **الختم:** `audit:seal` كل دقيقة يختم بسلسلة SHA-256 بترتيب `seal_seq`، ويكتب المرساة في `audit_seals` وفي `storage/app/private/audit-anchors/YYYY-MM.log`.
- **التحقق:** `audit:seal --verify` يوميًا 03:15 يعيد حساب السلسلة كلها. عند الانقطاع يسجل حدثًا حرجًا، ويظهر الأمر في «سلامة السجل».
- **حدود الحماية:** هذا **كشف** للعبث لا **منع** له. مالك الجدول (`al_amal_user`) يستطيع تعطيل المشغّلات، لكن التحقق يكشف التغيير (مُختبر). لاستقلال المراسي يُنسخ مجلد `audit-anchors` دوريًا خارج الخادم. ويُستحسن لاحقًا فصل دور مالك الجداول عن دور التطبيق.
- **الربط بين الطلبات:** `X-Request-Id` يُستقبل (إن كان آمنًا) أو يُولَّد ويُعاد في الاستجابة. أوامر artisan (المجدول، عامل الاستيراد) تحمل معرّف ربط لكل تشغيل.
- **الاحتفاظ:** لا مدة احتفاظ مفروضة ولا حذف؛ لم يحدد المالك سياسة بعد. أي أرشفة لاحقة تحتاج قرارًا وطريقًا خاصًا لا يتجاوز قاعدة الإضافة فقط.
