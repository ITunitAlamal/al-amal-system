# التقرير الفني لنظام AIMS

**موجّه إلى:** مجلس الإدارة  
**تاريخ إعداد التقرير:** 1 نوفمبر 2026  
**نطاق المراجعة:** ملفات الشيفرة والإعدادات والوثائق المتاحة في المستودع.  
**تنبيه:** هذا تقييم فني للمستودع، وليس شهادة تدقيق أمني أو اعتماد إطلاق أو تقرير تقدم صادرًا عن أداة إدارة مشاريع.

## 1. الملخص التنفيذي

نظام **AIMS** تطبيق مؤسسي لإدارة أعمال المؤسسة، مبني بنمط تطبيق ويب متكامل: واجهة تفاعلية عربية، وخدمات خلفية مركزية، وقاعدة بيانات علائقية. يغطي المستودع وظائف الموارد البشرية والحضور والإجازات والمالية والمشتريات والمخزون والعقارات والمراسلات الرسمية وإدارة الأيتام والكفالات والحملات وبوابة الأوصياء، إضافة إلى سير العمل والموافقات والتقارير.

توجد في المستودع تطبيقات وظيفية وخدمات وقاعدة بيانات واختبارات، كما توجد تقارير تنفيذ واختبار لبعض الوحدات. لكن وجود الشيفرة لا يثبت وحده اكتمال قبول المستخدمين أو جاهزية بيئة الإنتاج. لذلك يقدّر هذا التقرير **إنجاز التطوير البرمجي بنحو 74%** وفق منهج تقديري موضح أدناه، ولا يقدّم هذه النسبة على أنها نسبة إنجاز رسمية أو نسبة جاهزية للإطلاق.

**الخلاصة الإدارية:** النظام متقدم وظيفيًا ويضم وحدات أعمال مترابطة، لكن يلزم إكمال خط أساس متفق عليه للمتطلبات، واختبارات قبول موحّدة، والتحقق من التشغيل الفعلي والتكاملات والبيانات وبيئة الإنتاج قبل اعتماد موعد إطلاق أو إعلان جاهزية تشغيلية.

## 2. البنية التقنية

| الطبقة | التقنية | الاستخدام |
|---|---|---|
| واجهة الويب | Vue.js 3، JavaScript، Inertia.js 3 | صفحات تفاعلية تتصل بمسارات وخدمات Laravel من دون فصل الواجهة إلى تطبيق API مستقل بالكامل. |
| العرض والصفحات المساندة | Blade | نقطة تحميل Inertia وبعض صفحات الدخول والأخطاء والطباعة والقوالب. |
| التنسيق | Tailwind CSS 4 وملفات CSS خاصة بالنظام | تنسيق الواجهات ومكوّناتها. |
| البناء الأمامي | Vite 8 وملحقات Laravel وVue وTailwind | تجميع ملفات الواجهة وإنتاج الأصول الثابتة. |
| الخلفية | PHP 8.3 أو أحدث ضمن قيد Composer، وLaravel 13 ضمن القيد المعلن `^13.17` | المصادقة، المسارات، التحقق، الصلاحيات، منطق الأعمال، الملفات، التقارير، والخدمات. |
| تنظيم منطق الأعمال | Controllers وServices وModels وPolicies | فصل استقبال الطلبات عن قواعد المجال والتعامل مع البيانات والصلاحيات. |
| قاعدة البيانات | قاعدة علائقية عبر Eloquent وPDO وعمليات ترحيل Laravel | تخزين بيانات المؤسسة والمعاملات وسجل التغييرات. الإعداد الافتراضي في المستودع SQLite، مع تعريف اتصالات PostgreSQL وMySQL وMariaDB وSQL Server. |
| المهام الخلفية | Laravel Queue | الإعداد الافتراضي الظاهر هو قاعدة البيانات؛ توجد إعدادات اختيارية لـ Redis وSQS وغيرها. |
| الملفات | Laravel Filesystems | التخزين الافتراضي محلي، مع تعريف تخزين S3 اختياري. |
| تطبيق التوزيع الميداني | Electron لتطبيق Windows، مع مُثبّت NSIS | تنزيل قوائم التوزيع والعمل دون اتصال ثم مزامنة الأحداث. |
| جسر أجهزة الحضور | Python ومكتبة `pyzk` الاختيارية | قراءة سجلات أجهزة الحضور، مع وصف الأداة بأنها للقراءة فقط. |

**تمييز مهم:** إعدادات SQLite وQueue وقواعد البيانات والتخزين تصف القيم الافتراضية أو الخيارات المتاحة في الشيفرة. لا تكشف بمفردها أي قاعدة بيانات أو خدمة تخزين أو إعداد تشغيل تستخدمه بيئة الإنتاج فعليًا؛ ذلك يتطلب فحصًا مخولًا لبيئة النشر، وليس استنتاجًا من المستودع.

## 3. كيف تعمل المنظومة

1. يرسل المستخدم طلبًا من صفحة Vue/Inertia أو من نموذج Blade.
2. يمر الطلب عبر مسارات Laravel والوسائط المخصصة للمصادقة والتحقق من الصلاحيات.
3. يتولى Controller تنسيق الطلب، وتنفذ خدمات المجال قواعد العمل والموافقات.
4. تُقرأ البيانات وتُحفظ في قاعدة البيانات من خلال Eloquent أو استعلامات Laravel، مع استخدام معاملات وقواعد بيانات وفهارس حسب الحاجة.
5. تعاد نتيجة الصفحة وبياناتها عبر Inertia أو استجابة JSON للواجهات البرمجية، أو يُنشأ ملف تقرير/مرفق بحسب العملية.

تظهر في الشيفرة وحدات خدمات متخصصة للمجالات مثل المالية والموارد البشرية والحضور والإجازات والعقارات والمراسلات والأيتام وسير العمل. وتضم قاعدة البيانات أكثر من مئة ملف ترحيل، ما يعكس توسعًا تدريجيًا في نموذج البيانات. وتُدار التغييرات الهيكلية عبر ملفات migrations بدل تعديل بنية الجداول يدويًا بوصفه مسار التطبيق.

## 4. الوظائف الرئيسية المنفذة

- **الهوية والإدارة:** حسابات مستخدمين، أدوار وصلاحيات، وحدات تنظيمية، إعدادات وقوائم النظام، وتدقيق بعض الإجراءات.
- **الموارد البشرية:** ملفات الموظفين، المسميات والدرجات، بيانات الخدمة والملفات، وبعض عمليات التغيير الوظيفي.
- **الحضور والإجازات:** سجلات الحضور، الجداول والورديات والطلبات والتصحيحات، أرصدة الإجازات ومسارات الموافقة.
- **المالية:** معاملات وسندات ومستحقات، مشتريات وعروض أسعار وأوامر شراء وفواتير وتسويات وتقارير، إضافة إلى عمليات الميزانية والمخزون.
- **العقارات والإيجارات:** الوحدات والعقود والتحصيل والصيانة والإجراءات المرتبطة بها.
- **المراسلات الرسمية:** سجل المراسلات والإحالات والمرفقات وسير العمل والطباعة والإصدارات. وثائق الإصدار V3.1 تصف بعض السياسات والإجراءات بأنها جزئية أو معلقة بقرارات حوكمة.
- **الأيتام والأوصياء:** سجل المستفيدين والأوصياء، طلبات البوابة ومراجعتها، الكفالات والمساعدات والحملات والتقارير والاستيراد.
- **التوزيع الميداني:** واجهة API وتطبيق Windows للمزامنة مع دعم العمل غير المتصل وفق حدود موثقة.
- **المؤشرات ولوحات العمل:** خدمات KPI، ولوحات بحسب الصلاحية، والإشعارات والمهام ومساحات الأقسام.

## 5. قاعدة البيانات والبيانات

النموذج علائقي ومجزأ إلى جداول بحسب المجال، مع علاقات بين المستخدمين والموظفين والوحدات التنظيمية والمعاملات وسير العمل. وتوضح وثائق وحدة الأيتام وجود سجلات تاريخية منفصلة للعناوين والحالات والتقييمات والوصاية والتعليم والمساعدات والحملات، مع هدف تجنب تكرار الشخص بين أفراد الأسرة.

تشير الوثائق والشيفرة إلى ضوابط مثل تشفير حقول شخصية أو صحية محددة، تسجيل بعض عمليات الاطلاع والتصدير، وإبقاء ملفات ومرفقات في تخزين خاص بحسب التدفق. هذه أوصاف للضوابط الموجودة في التنفيذ والوثائق؛ ولا تعادل فحصًا تشفيريًا مستقلًا أو تدقيقًا لسياسات الاحتفاظ والنسخ الاحتياطي.

## 6. الأمن والصلاحيات والتكاملات

- يعرّف النظام حارسين لجلسات الدخول: مستخدم النظام والوصي، إضافة إلى مصادقة خاصة بجهاز تطبيق التوزيع.
- مسارات المالية والمراسلات والموارد البشرية وغيرها تمر عبر مصادقة Laravel، وتوجد خدمات للتحقق من الوصول ونطاق البيانات.
- وثائق التوزيع الميداني تصف ربط الجهاز، وتوقيع الأحداث، وقائمة توزيع محددة، ومزامنة قابلة لإعادة المحاولة، وتخزينًا محليًا مشفرًا. كما تنبه إلى مخاطر متبقية للعمل دون اتصال وإدارة الأجهزة.
- جسر الحضور موصوف كقارئ للأحداث من أجهزة متوافقة، ولا ينبغي اعتباره تكاملًا إنتاجيًا معتمدًا قبل اختباره على الأجهزة والبرامج الثابتة الفعلية.
- إعدادات البريد والتخزين والصفوف الخلفية متاحة، لكن التفعيل والربط الخارجي والإعدادات الفعلية لا تثبتها ملفات المصدر وحدها.

لا يتضمن هذا التقرير اختبار اختراق أو فحصًا أمنيًا مستقلًا، ولا يثبت سلامة إعدادات الخادم أو المفاتيح أو الحسابات في الإنتاج.

## 7. الاختبارات والتحقق

يحتوي المستودع على اختبارات PHP من نوع Feature، واختبارات JavaScript/Node، واختبار Python لجسر القراءة، إضافة إلى وثائق نتائج اختبار لبعض الوحدات. وتوثق تقارير المراسلات اختبارات آلية وبناء واجهة لوحدات محددة، لكنها تسجل كذلك حدودًا مثل عدم التحقق البصري الكامل وعدم تنفيذ بعض سياسات الحوكمة أو اختبار الإطلاق الإنتاجي.

**في إعداد هذا التقرير لم تُشغّل مجموعة الاختبارات أو بناء التطبيق من جديد.** لذلك يُعرض وجود الاختبارات والنتائج المسجلة كدليل موثق في الملفات، لا كنتيجة تحقق جديدة لهذا التقرير. كما أن نجاح اختبار وحدة منفردة لا يثبت نجاح اختبار قبول شامل للنظام.

## 8. تقدير التقدم والإنجاز

### المنهجية والحدود

لا يظهر في المواد التي تمت مراجعتها خط أساس رسمي موحد يحدد قائمة المتطلبات المعتمدة وأوزانها، ولا سجل نقاط إنجاز موثوق يمكن حساب النسبة منه. لذلك فإن الأرقام أدناه **تقدير فني نوعي** لحالة كل مسار بحسب وجود وظائف في الشيفرة، والوثائق والاختبارات الظاهرة، والقيود المعلنة. المتوسط يحسب المجالات الثمانية بأوزان متساوية؛ ولا يمثل ساعات العمل أو نسبة المتطلبات المقبولة أو الجاهزية الإنتاجية.

| مجال العمل | الإنجاز التقديري | المبرر المختصر |
|---|---:|---|
| المنصة الأساسية والصلاحيات وسير العمل | 85% | أساس Laravel، المصادقة والأدوار والخدمات ومسارات الموافقات ولوحات العمل موجود؛ لم يثبت قبول شامل لكل الأدوار والعمليات. |
| الموارد البشرية والإجازات والحضور | 80% | وحدات وشاشات وخدمات وترحيلات متعددة موجودة، مع جسر أجهزة؛ يلزم تحقق تشغيلي على الأجهزة والبيانات الفعلية واختبار قبول موحد. |
| المالية والمشتريات والمخزون | 75% | تدفقات معاملات وتقارير ومشتريات ومخزون ظاهرة في الشيفرة؛ يلزم اختبار المطابقة والتسويات والصلاحيات مع المستخدمين والبيانات التشغيلية. |
| المراسلات الرسمية | 80% | وحدة واسعة موثقة ومختبرة في تقاريرها؛ تبقى قرارات حوكمة وسياسات خارجية واختبارات إطلاق محددة معلقة بحسب تقرير الوحدة. |
| الأيتام والأوصياء والكفالات | 78% | تنفيذ موثق واسع وسيناريوهات أعمال متعددة؛ ما زالت بعض البيانات المرجعية والقرارات والتجارب اليدوية/الميدانية مطلوبة. |
| العقارات والإيجارات | 70% | نماذج وخدمات ومسارات إدارية ومالية موجودة؛ لم يظهر في المراجعة تقرير قبول نهائي شامل لهذا المجال. |
| تطبيق التوزيع والتكاملات | 70% | عقد API وتطبيق Windows وجسر حضور موجودة؛ تقارير الوحدة تشير إلى ضرورة التحقق على أجهزة فعلية وإعداد الإنتاج. |
| الاختبار الشامل والقبول والإطلاق | 50% | توجد اختبارات ووثائق جزئية، لكن لا يوجد في المواد التي تمت مراجعتها إثبات قبول شامل أو تحقق نشر/استعادة إنتاجية مكتمل. |
| **المتوسط التقديري المتساوي** | **نحو 74%** | **متوسط المجالات أعلاه، بعد التقريب.** |

### تفسير النسبة

- **نحو 74% هو تقدير إنجاز التطوير البرمجي الظاهر في المستودع**، وليس مؤشرًا رسميًا تعاقديًا.
- **نسبة جاهزية الإنتاج غير مثبتة** ولا ينبغي مساواتها بـ74%. يلزم لتحديدها التحقق من بيئة الإنتاج، والترحيلات والنسخ الاحتياطي والاستعادة، والأمن، والتكاملات، وتوقيع المستخدمين على القبول.
- الثقة في التقدير **متوسطة إلى منخفضة** بسبب غياب خط أساس معتمد ومؤشرات تقدم موحدة، وبسبب اختلاف مستوى التحقق بين الوحدات.

## 9. الأعمال المقترحة قبل اعتماد الإطلاق

1. اعتماد قائمة متطلبات موحدة ومصفوفة قبول لكل وحدة، وتثبيت الأوزان والمالك المسؤول عن كل بند.
2. توثيق بيئات التطوير والاختبار والإنتاج، ونوع قاعدة البيانات الفعلي، ومخطط النسخ الاحتياطي وخطة الاستعادة.
3. استكمال قرارات الحوكمة والصلاحيات التي تسجلها تقارير المراسلات، وقرارات البيانات والإعدادات التشغيلية لوحدة الأيتام.
4. إجراء اختبارات قبول من المستخدمين على أدوار متعددة، واختبار المتصفح والطباعة والأجهزة الفعلية وتطبيق التوزيع دون اتصال.
5. تنفيذ اختبار تكامل واختبار رجوع للترحيلات، ثم اختبار النسخ الاحتياطي والاستعادة على بيئة مرحلية.
6. اعتماد مراجعة أمنية مستقلة قبل الإنتاج، بما يشمل صلاحيات الوصول، وحماية البيانات، وإدارة الأسرار، وسجلات التدقيق، والتخزين والمرفقات.
7. إصدار تقرير إطلاق منفصل بعد اكتمال الاختبارات، يتضمن النتائج الفعلية، والعيوب المتبقية، وخطة الدعم والتدريب.
