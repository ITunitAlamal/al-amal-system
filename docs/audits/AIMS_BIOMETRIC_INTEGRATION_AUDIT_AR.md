# تدقيق وتطوير تكامل أجهزة الحضور ZKTeco في AIMS

التاريخ: 2026-10-28. المشروع: `C:/Projects/al-amal-system`.

## النتيجة وحالة النشر

طُورت وحدة الحضور القائمة دون إنشاء نظام موازٍ: إعدادات الأجهزة، فحص البروتوكول، الحالة المخزنة، معاينة الاستيراد واعتماده، حفظ الخام، مراجعة غير المطابق ومنع الازدواجية.

**لم ينفذ الترحيل الجديد على قاعدة AIMS الفعلية ولم تستورد إليها أي حركة أثناء العمل.** يتوقف أمر الاستيراد بوضوح قبل نشر الترحيل، بدل العودة إلى المسار القديم الذي فسّر الرموز وأسقط غير المطابق.

الموجود عامل Laravel محلي موثوق يستعمل Python/pyzk، وليس وكيلًا مستقلاً يرفع البيانات إلى VPS عبر HTTPS. نقل الوكيل البعيد ومصادقته وتدوير مفاتيحه لم ينفذ أو يختبر. التشغيل المحلي تحقق فعليًا؛ الوصول من VPS إلى LAN يحتاج قناة خاصة مُدارة أو تنفيذ النقل الآمن المستقل قبل اعتماده.

قُرئ AGENTS.md والمهارات المتعلقة بـ Laravel وInertia Vue والاختبارات وTailwind. لم يوجد مجلد `.ai/rules`. عمل Laravel Boost و`search-docs` فعليًا. استُخدمت الإصدارات المثبتة؛ لم تغيّر التبعيات، ولم تستخدم صور أو أتمتة متصفح أو اختبارات بصرية.

## حفظ البيانات والازدواجية

- يعاد استخدام attendance_punches. يحفظ raw_payload حقول uid والتوقيت وstatus وpunch وtype وdevice_event_id. الأعمدة الإضافية تحفظ المنطقة الزمنية ورقم التكرار ومرجع التشغيل؛ created_at وقت الاستيراد. direction تبقى unknown.
- الأرقام تطابق نصيًا مع حفظ الأصفار، دون إنشاء موظفين. غير المطابق محفوظ مع employee_id فارغ، والربط القديم المتعارض لا يتجاوز الرقم الوظيفي.
- البصمة من الحقول الخام ومعرّف الجهاز، ومعها occurrence للنسخ المتطابقة داخل اللقطة. الإعادة لا تضيف صفوفًا وتصل الأحداث المتأخرة دون الاعتماد على max(timestamp). لا يفترض أن pyzk uid رقم حدث فريد.
- القيد source_key الفريد والمعاملة وقفل سجل الجهاز يحميان الكتابة. قفل `attendance-device-io:{id}` ينسق القراءة والفحص؛ يلزم cache مشترك يدعم الأقفال الذرية بين العمليات.
- تحفظ اللقطة مشفرة مع MAC عبر Laravel Crypt داخل `storage/app/private/attendance-retry` قبل الكتابة. تعاد عند الفشل وتحذف نسخة النقل بعد نجاح الحفظ فقط؛ لا يحذف سجل الجهاز أو السجل الخام. احمِ المجلد وAPP_KEY ونسخه الاحتياطية. تغيير الإعدادات يترك النسخة القديمة محفوظة ولا يعيدها تحت إعدادات جديدة.
- اللقطة غير الصالحة ترفض كاملة وتبقى مشفرة؛ لا إسقاط صامت لصف. أوقات DST غير الموجودة أو الملتبسة باختلاف ساعة ترفض بدل اختيار تفسير. التوقيت المحلي يحفظ كسور الثانية إن وجدت؛ occurred_at الحالي بدقة الثانية.
- إذا مسح طرف آخر ذاكرة الجهاز أو أعاد استخدام هويات وأحداث متطابقة بالكامل، لا يمكن تمييز بعض الأحداث الجديدة دون هوية مستقرة. الانتقالات الزمنية غير الاعتيادية المختلفة عن ساعة تحتاج تحققًا إضافيًا.
- الحركات القديمة لا تحذف أو تعدل؛ مفاتيح zk القديمة تختلف عن zkraw، ولا يمكن استعادة حقول خام مفقودة بأثر رجعي. راجع السجلات السابقة للجهاز قبل أول نشر إن وجدت.
- الجديدة في المعاينة عدد متوقع، وليست صفوفًا مكتوبة. received عناصر اللقطة، duplicates الموجودة بمفتاحها، unmatched عناصر اللقطة غير المطابقة، وfailed عناصر اللقطة المرفوضة عند فشلها. خطأ اتصال دون لقطة يظهر بحالة failed ولو كانت الأعداد صفرًا.

## الترحيل والنشر الآمن

الملف: `database/migrations/2026_10_28_091603_add_safe_raw_attendance_import.php`.

يضيف أعمدة للجداول الموجودة، ويسمح بـ employee_id فارغ، ويضيف مراجع الاعتماد والتشغيل. مشغل PostgreSQL يمنع تغيير أو حذف أصل الحركة الخام. لا يزيل بيانات قديمة. نفذ داخل معاملات الاختبار فقط؛ لم يستخدم migrate:fresh أو refresh أو db:wipe.

يرفض down حذف أدلة الحضور عمدًا. عند تعثر النشر عطّل الاستيراد واستعمل ترحيل إصلاح أمامي؛ لا تعد إلى المستورد القديم وهو مفعّل. راجع قفل ALTER TABLE والتوافق والحجم ونسخة احتياطية قابلة للاستعادة قبل النشر.

هذه خطوات لمسؤول النشر، وليست أوامر نفذت على الإنتاج:

1. أوقف جدولة الحضور مؤقتًا وخذ نسخة PostgreSQL متحققًا من استعادتها. راجع الترحيلات المطلوبة فقط.
2. تأكد من نشر ترحيل الصحة السابق، ثم بعد اعتماد النشر نفذ `php artisan migrate --path=database/migrations/2026_10_28_091603_add_safe_raw_attendance_import.php --no-interaction`.
3. حدد ATTENDANCE_AGENT_ID وATTENDANCE_ZK_PYTHON لمسار Python المحلي المعتمد. النسخة المجربة pyzk 0.9؛ لم تثبت تبعيات جديدة.
4. عرّف ATTENDANCE_AGENT_DESTINATIONS كمصفوفة JSON من agent وhost وport وdevice_id اختياري. البديل القديم ATTENDANCE_ZK_ALLOWED_HOSTS وATTENDANCE_ZK_ALLOWED_PORTS يظل مقيدًا بالوكيل المحلي. يحتاج الإنشاء إذن عنوان/منفذ أوليًا قبل تضييق القائمة إلى معرّف الجهاز.
5. فعّل ATTENDANCE_HEALTH_PROBE_ENABLED للفحص، وATTENDANCE_ZK_SYNC_ENABLED للقراءة، وATTENDANCE_SCHEDULE_ENABLED للطلبات والجدولة. أبقِ ATTENDANCE_CALCULATION_SCHEDULE_ENABLED=false حتى اعتماد الحسابات منفصلًا.
6. شغّل `php artisan schedule:work` بحساب خدمة محدود على محطة LAN موثوقة. الفحص كل 30 ثانية، والمزامنة تراجع الطلبات كل دقيقة وتحترم sync_interval_seconds لكل جهاز. لم تثبت خدمة Windows. يلزم مخزن أقفال مشترك؛ لا تشغّل موصلًا آخر غير منسق.
7. لا تكشف PostgreSQL أو منفذ الجهاز للإنترنت. VPS لا يصل إلى 172.16.x.x تلقائيًا. لا تنسخ أسرار التطبيق لمحطة غير موثوقة. الوكيل المستقل ذو نقل HTTPS ومصادقة محدودة الأجهزة غير منفذ.

## قائمة المشغّل

1. افتح الحضور ← أجهزة البصمة بحساب مخول. أدخل الاسم والموقع وIPv4/المنفذ المعتمدين والبروتوكول والوكيل وpyzk والمنطقة الزمنية والمهل والفواصل. لا تفترض المنطقة الزمنية من IP. السر مشفر؛ الفراغ عند التعديل يبقيه والقيمة 0 تضبطه إلى صفر صراحة.
2. بمدير النظام اعتمد اتصال الفحص ثم «اختبار الاتصال». افحص الجهاز والوكيل كلًا على حدة وآخر نجاح/فشل وTTL. تحديث الصفحة كل ثانيتين لا يعني اتصالًا فعليًا كل ثانيتين. البيانات القديمة ليست إثبات اتصال.
3. فعّل pull ثم «معاينة الاستيراد الأول». التفعيل لا يجيز الاستيراد الأول. يمكن استعمال `php artisan attendance:sync --device=DEVICE_ID --dry-run` بعد إعداد السياسات.
4. افتح العمليات وراجع المستلمة والجديدة المتوقعة والمكررة وغير المطابقة والفاشلة. اللقطة المشفرة هي المعاينة؛ الأحداث الأحدث تصل بدورة لاحقة.
5. احصل على موافقة المشغّل الصريحة. «اعتماد الاستيراد الخام» يتطلب تأكيدًا ومعاينة ناجحة خلال 24 ساعة للإعدادات نفسها ويسجل المستخدم والتشغيل. **لم تُمنح هذه الموافقة في الجلسة الحالية.**
6. بعد الموافقة، «مزامنة الآن» أو الجدولة تستورد الخام. لا يجيز ذلك تفسير punch أو خصومات؛ الفشل يبقي نسخة الإعادة.
7. راجع أول 100 حركة غير مطابقة. صحح الرقم الوظيفي عبر HR دون إزالة أصفار أو اختيار employees.id. «إعادة المطابقة بعد التصحيح» تحتاج سببًا وتطابقًا وحيدًا. الربط القديم المتعارض يحتاج معالجة موثقة ولا يتجاوز تلقائيًا.
8. أعد اللقطة نفسها: المتوقع inserted=0 وduplicates يساوي الخام الموجود. الأحداث الجديدة والمتأخرة فقط تضاف. لا تشترط بقاء العدد 5,324 أو 5,388.

## الاختبارات وحدود الإنجاز

قاعدة الاختبار PostgreSQL: `127.0.0.1:55440 / aims_correspondence_test_20261022`. تحقق اسمها والمنفذ قبل الكتابة وفي كل إعداد اختبار. البيانات والترحيل داخل rollback؛ اختبارات HTTP القائمة الأخرى تستخدم SQLite :memory:. لا تستبدلها بقاعدة AIMS.

يغطي AttendanceRawImportTest الإعادة والأحداث المتأخرة وتعدد النسخ والرموز والزمن والأصفار والمطابقة المتعارضة والملتبسة، والمعاينة والاعتماد وRBAC والتدقيق والأسرار والنسخة المشفرة والفشل دون حفظ جزئي، وقفل القراءة والجدولة وتعيين الوكيل، ومنع تعديل/حذف الخام في PostgreSQL ومراجعة المطابقة. تغطي اختبارات الصحة والعمليات Inertia وJSON وTTL والصلاحيات. يستخدم Python جهازًا وهميًا لا يتيح أوامر التغيير؛ يختبر JavaScript فترة 2000ms وعدم التداخل والإخفاء والتنظيف.

نتائج الجولة النهائية تضاف بعد انتهاء التحقق.

المتبقي صراحة:

- نشر الترحيل بعد المراجعة ثم موافقة أول استيراد. لم تختبر إعادة استيراد إنتاجي؛ إثبات idempotency ببيانات اصطناعية.
- اعتماد سياسة رموز الجهاز وتحويل الخام إلى حضور/انصراف وحسابات، دون استنتاج من status=1.
- الوكيل البعيد المستقل ومصادقة outbound HTTPS وتدوير المفاتيح: غير منفذ وغير مختبر.
- لا اختبار قتل عملية/انقطاع طاقة أو fsync، ولا ضغط إنتاجي أو عمليتين مستقلتين متزامنتين. اختبار القفل والقيود لا يعادل هذه الحالات.
- مراجعة الربط القديم والأزمنة الملتبسة والسجلات السابقة دون حذف صامت.
- لا اختبار بصري. نجح بناء Vite مع تحذيرات خطوط WOFF2 موجودة غير محلولة وقت البناء؛ لم تغيّر الخطوط.
