# خطة تحديث الواجهات — وما نُفذ منها (2026-11-01)

## المبدأ
- تحديث طبقة العرض فقط، دون تغيير منطق الأعمال أو قواعد البيانات (لا migrations في هذا العمل).
- كل رقم يأتي من استعلام في الخادم بنطاق صلاحية المستخدم.
- ما لا مصدر له يُعرض «غير متاح» مع السبب.

## المراحل

| المرحلة | المحتوى | الحالة |
|---|---|---|
| A | الحصر والخطة (`UI_UX_SCREEN_INVENTORY.md`) | ✔ |
| B | مكونات اللوحات المشتركة: المؤشر، الخط الزمني، الأعمدة الأفقية، جدول الإجراءات، اللوحة، الهيكل المؤقت. الرموز والخطوط القائمة كما هي | ✔ |
| C | لوحات: المدير التنفيذي، رئيس قسم الأيتام، والتسجيل والبحث الاجتماعي والكفالات والحملات | ✔ |
| D | لوحات: الموارد البشرية، والحسابات، والإيجارات، ورئيس القسم (العلاقات العامة وتكنولوجيا المعلومات والسكرتاريا ومكتب المدير)، ومدير النظام، والموظف | ✔ |
| E | الاستيراد الذكي: إصلاح «resolution» والإلغاء الذري؛ اختصار «تسجيل أسرة» | ✔ جزئيًا |
| F | بوابة المستفيدين: 8 صفحات ناقصة، والرئيسية بمراحل الطلب، ومنتقي العنوان | ✔ |
| G | التحقق النصي (بناء، فحص، طلبات HTTP، صلاحيات) | ✔ (دون لقطات شاشة بقرار المالك) |

### المرحلة E — المتبقي
لم يُعَد تصميم صفحات السجل والمراجعات والحملات والمالية. هي تعمل وتتبع نظام التصميم القائم. يلزمها لاحقًا:
- مقارنة قبل/بعد موحدة.
- درج معاينة موحد.

## المتبقي (للمالك)
- **مقاييس العلاقات العامة (النشر والتفاعل):** لا مصدر لها؛ تُعرض «غير متاح».
- **الحسابات:** الانحراف عن الموازنة والإيرادات والمصروفات الشهرية غير متاحة، لأن الدفاتر في نظام «القلعة الأصيل». يلزم إسناد صلاحيات مالية لرئيس الحسابات ليرى لوحة الاعتمادات بدل لوحة القسم.
- **وحدات الأيتام:** لا موظفين مسندين لها بعد؛ تظهر لوحاتها عند الإسناد.
- **الأجهزة:** فحص بصري على أحجام الشاشات لم يُجرَ (لا لقطات ولا متصفح آلي بقرار المالك). التخطيط يعتمد شبكات Tailwind المتجاوبة وجداول تتحول إلى بطاقات على الجوال.

## التشغيل
- `npm run build` بعد السحب.
- لا migrations جديدة.
- لا إعدادات جديدة.
